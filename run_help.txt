LaudareDataset Benchmarking Framework - Main Workflow Script

USAGE:
  ./run.sh [OPTIONS]

DESCRIPTION:
  Runs OCR, OMR, and layout benchmarks and prepares annotations or synthetic data.
  The workflow supports single-fold, N-fold cross-validation, sequential learning,
  and custom train/test directory modes.

  Data preparation processes an edition-specific COCO annotation file into folds
  and sequential splits. Benchmark outputs use the experiment ID from
  LAUDARE_EXPERIMENT_ID (default: "default").

  MANDATORY PARAMETERS: --task
  For ocr, omr, and layout tasks: --edition and --framework are mandatory.
  Annotation preparation requires --data-dir and --edition. Dataset benchmarks
  also require --data-dir. --model-name defaults to "default".


WORKFLOW CONTROL OPTIONS:
  --help                     Show this help message and exit.
  --debug                    Enable debug mode with a reduced dataset and fewer training steps/folds.
  --device DEVICE            Specify the training device (default: cuda:0).
                             Examples: cuda:0, cpu; NOTE: this option works by overriding
                             the CUDA_VISIBLE_DEVICES environment variable, so you should not
                             set it manually.
  --edition EDITION          [MANDATORY for ocr, omr, layout] Choose the edition type.
                             Options: diplomatic, editorial
  --editorial                Shortcut for '--edition editorial'.
  --framework FRAMEWORK      [MANDATORY for ocr, omr, layout] Framework from
                             benchmarking/models.json for the selected task.
                             Examples: kraken, calamari, trocr, bgk, yolo, detr,
                             faster-rcnn, doclayout_yolo, paddleocr_vl,
                             paddleocr_vl_e2e.
  --task TASK                [MANDATORY] Options: annotations, ocr, omr, layout,
                             synthesis. (ocmr is also accepted by the runner.)
  --data-dir DIR             Dataset root containing annotations-{edition}/gt.json.
                             Required for annotation preparation and dataset benchmarks.
                             Supply this explicitly for custom datasets.
  --train-dir DIR            Custom training directory (for train/test mode).
  --test-dir DIR             Custom testing directory (for train/test mode).
  --augment BOOL             Enable/disable data augmentation (default: true).

MODEL AND FOLD OPTIONS:
  --fold N                   In single fold mode, specify which fold to run (default: 0).
  --model-name NAME          Selects the model configuration from 'benchmarking/models.json'
                             for the specified framework and task using the model name as key (default: "default").

EXECUTION MODES:
  --n-fold                   Enable N-fold cross-validation mode. Runs on all folds and aggregates results.
  --strategy S               Enable sequential learning mode with the specified strategy.
                             Options: random_sample, sequential_sample

PRE-TRAINING OPTIONS:
  --enable-pretrain          Enable pre-training on synthetic data. Note that if a pre-trained model is found in the standard directory, it is loaded and pre-training is skipped.
  --pretrain-dir DIR         Custom directory for pre-training data (overrides default synthetic data from ./data/pretrain_data/).
                             When provided, models will be named with the directory basename to avoid conflicts.
  --pretrain-samples N       Number of synthetic samples to generate. Sets OCR samples to N and OMR samples to N/20 (default: OCR=5000, OMR=250).
  --font-dir DIR             Directory with fonts for OCR data generation (default: ./fonts).
  --capitals-dir DIR         Directory with decorative capital fonts (default: ./fonts/capitals).
  --latex-jobs N             Number of parallel LaTeX jobs for OMR data generation (default: 8).
                             
  Note: Pre-training data is generated during the 'synthesis' task step and saved in ./data/pretrain_data/.

EXAMPLES:
  # Run a single benchmark on fold 0 for OCR with Kraken.
  ./run.sh --framework kraken --model-name default --task ocr \
    --data-dir data/I-Ct_91 --edition diplomatic

  # Run N-fold cross-validation for Kraken OCR on the editorial edition.
  ./run.sh --n-fold --framework kraken --model-name default --task ocr \
    --data-dir data/I-Ct_91 --edition editorial

  # Run sequential OMR with Calamari.
  ./run.sh --strategy random_sample --framework calamari --model-name default \
    --task omr --data-dir data/I-Ct_91 --edition diplomatic

  # Run YOLO layout on fold 2 in debug mode.
  ./run.sh --framework yolo --model-name yolo26s --task layout \
    --data-dir data/I-Ct_91 --edition diplomatic --fold 2 --debug

  # Generate pre-training data
  ./run.sh --task synthesis

  # Prepare folds and sequential splits for a custom dataset.
  ./run.sh --task annotations --data-dir data/my_dataset --edition diplomatic

  # Run OCR on a custom dataset, fold 0.
  ./run.sh --framework kraken --model-name default --task ocr \
    --data-dir data/my_dataset --edition diplomatic --fold 0

  # Generate annotations for the default dataset.
  ./run.sh --task annotations --data-dir data/I-Ct_91 --edition diplomatic

OUTPUT:
  - Master annotations: data/{dataset}/annotations-{edition}/gt.json
  - Prepared folds and sequential splits:
    data/{dataset}/annotations-{edition}/processed_splits/
  - Annotation preparation also writes train.json and val.json beside gt.json.
  - Models and benchmark results are isolated under
    ./models/${LAUDARE_EXPERIMENT_ID:-default}/ and
    ./results/${LAUDARE_EXPERIMENT_ID:-default}/.
  - Benchmark results are organized by dataset and edition below the experiment
    results directory; N-fold aggregates are in the aggregated/ subdirectory.
  - Synthetic pre-training data is in ./data/pretrain_data/.

REQUIREMENTS:
  - Master annotation files in data/{dataset}/annotations-{edition}/gt.json
  - 'uv' Python package manager installed
  - GPU with CUDA support (recommended for performance)
  - Virtual environments set up for framework-specific dependencies (kraken, calamari)
